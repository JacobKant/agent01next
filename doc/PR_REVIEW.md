f# Автоматическое ревью Pull Request

Система автоматического ревью PR использует AI агента с RAG и MCP инструментами для анализа изменений в Pull Request.

## Возможности

- ✅ Автоматический анализ изменений в PR
- ✅ Использование RAG для поиска контекста из документации проекта
- ✅ Получение diff и файлов через MCP инструменты
- ✅ Детальное ревью с замечаниями и предложениями
- ✅ Интеграция с GitHub Actions

## Использование

### Локальный запуск

```bash
# Ревью изменений между ветками
npm run pr-review -- --base main --head feature-branch

# Ревью текущих изменений относительно main
npm run pr-review -- --base main --head HEAD

# С дополнительными параметрами
npm run pr-review -- --base main --head HEAD --model "mistralai/devstral-2512:free" --temperature 0.7
```

### Параметры

- `--base <branch>` - Базовая ветка для сравнения (по умолчанию: main)
- `--head <branch>` - Ветка с изменениями (по умолчанию: HEAD)
- `--pr-number <number>` - Номер PR (опционально)
- `--model <model>` - Модель для использования (опционально)
- `--temperature <value>` - Температура генерации (по умолчанию: 0.7)

## GitHub Actions

Автоматическое ревью запускается при:
- Открытии нового PR
- Обновлении PR (synchronize)
- Повторном открытии PR

### Настройка

1. **Добавьте секрет `OPENROUTER_API_KEY` в настройках репозитория GitHub:**
   
   **Способ 1: Через веб-интерфейс GitHub**
   - Перейдите в репозиторий на GitHub
   - Откройте: **Settings** → **Secrets and variables** → **Actions**
   - Нажмите **New repository secret**
   - Name: `OPENROUTER_API_KEY`
   - Value: ваш API ключ OpenRouter (можно получить на https://openrouter.ai/keys)
   - Нажмите **Add secret**
   
   **Способ 2: Через GitHub CLI**
   ```bash
   gh secret set OPENROUTER_API_KEY --repo <owner>/<repo>
   ```
   (Вам будет предложено ввести значение ключа)

2. **Проверка настройки:**
   - После добавления секрета, он будет доступен в GitHub Actions
   - При запуске workflow переменная `OPENROUTER_API_KEY` будет автоматически подставлена
   - Если ключ не установлен, workflow выдаст понятную ошибку с инструкциями

3. **Workflow автоматически:**
   - Получает diff изменений
   - Запускает агента для анализа
   - Создает комментарий в PR с результатами ревью
   - Обновляет комментарий при новых изменениях

## Как работает ревью

1. **Получение изменений**: Используется `git_diff` для получения diff между ветками
2. **Поиск контекста**: Используется `search_rag` для поиска документации и правил проекта
3. **Анализ файлов**: Используется `read_project_file` для чтения измененных файлов
4. **Генерация ревью**: Агент анализирует изменения и создает структурированное ревью

## Формат ревью

Ревью включает:

- 📋 **Резюме изменений** - краткое описание изменений
- ✅ **Положительные моменты** - что сделано хорошо
- ⚠️ **Замечания и предложения**:
  - Критичные (требуют исправления)
  - Важные (желательно исправить)
  - Предложения по улучшению
- 📝 **Детальный анализ** - по файлам и строкам
- 🔍 **Использованные источники** - ссылки на документацию и коммиты

## MCP Инструменты

Система использует следующие MCP инструменты:

- `git_diff` - получение diff между ветками
- `git_log` - просмотр истории коммитов
- `read_project_file` - чтение файлов проекта
- `search_rag` - поиск в документации проекта

## Требования

- Node.js 20+
- Git репозиторий
- OPENROUTER_API_KEY в переменных окружения
- Индексированная RAG база знаний (для использования search_rag)

## Troubleshooting

### Ошибка "OPENROUTER_API_KEY не найден"

Убедитесь, что переменная окружения `OPENROUTER_API_KEY` установлена:
```bash
export OPENROUTER_API_KEY=your_key_here
```

### Ошибка "Индекс не найден" при использовании search_rag

Запустите индексацию документов:
```bash
cd document_indexer
npm install
npm run index
```

### Ошибка "not a git repository"

Убедитесь, что вы находитесь в корне git репозитория.
