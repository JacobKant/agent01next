# Документация по RAG индексации документов

## Обзор

Подпроект `document_indexer` предназначен для индексации документов с целью последующего использования в RAG (Retrieval-Augmented Generation) системе. Система использует векторную базу данных Vectra для хранения эмбеддингов и семантического поиска.

## Архитектура

### Компоненты

1. **Индексатор** (`index.ts`) - Разбивает документы на чанки и создает эмбеддинги
2. **Поиск** (`search.ts`) - Тестовый поиск по индексированным документам
3. **Эмбеддинги** (`embeddings.ts`) - Генерация эмбеддингов через OpenRouter API
4. **Векторная БД** (`vectra_index/`) - Локальное хранилище векторов

### Технологии

- **Vectra** - Локальная векторная база данных
- **OpenRouter API** - Генерация эмбеддингов через модель `qwen/qwen3-embedding-8b`
- **TypeScript** - Типизированный код

## Установка

```bash
cd document_indexer
npm install
```

### Переменные окружения

└── embeddings.ts         # Модуль эмбеддингов

## Использование

### Индексация документов

1. Поместите документы в `document_indexer/data/rawData/`

2. Запустите индексацию:

```bash
npm start
```

Скрипт:
- Читает документы из `data/rawData/`
- Разбивает текст на чанки (1200 символов с перекрытием 200)
- Генерирует эмбеддинги через OpenRouter API
- Сохраняет их в локальную базу данных Vectra

### Поиск в индексе

Запустите тестовый поиск:

```bash
npm run search
```

Скрипт:
- Запрашивает поисковый запрос у пользователя
- Генерирует эмбеддинг запроса
- Ищет наиболее релевантные документы в индексе
- Выводит топ-5 результатов с релевантностью и контекстом

## Параметры индексации

### Размер чанка

По умолчанию используется:
- **Размер чанка**: 1200 символов
- **Перекрытие**: 200 символов

Эти параметры можно изменить в `index.ts`:

```typescript
const CHUNK_SIZE = 1200;      // Размер чанка
const CHUNK_OVERLAP = 200;    // Перекрытие между чанками
```

### Модель эмбеддингов

По умолчанию используется `qwen/qwen3-embedding-8b` через OpenRouter API.

Модель можно изменить в `embeddings.ts`:

```typescript
const EMBEDDING_MODEL = "qwen/qwen3-embedding-8b";
```

## Интеграция с основным приложением

### MCP RAG Server

Основное приложение использует индекс через MCP сервер `rag-server.ts`:

```typescript
// Путь к индексу
const INDEX_PATH = join(process.cwd(), "document_indexer", "vectra_index");
```

### Использование в чате

AI может использовать инструмент `search_rag` для поиска информации в индексированных документах:

```
Пользователь: "Что такое оборотные активы?"
AI: [вызывает search_rag с query="оборотные активы"]
AI: [получает релевантные фрагменты и отвечает на основе них]
```

## Формат данных

### Метаданные чанка

Каждый чанк сохраняется с метаданными:

```typescript
{
  text: string;              // Текст чанка
  documentPath: string;       // Путь к исходному документу
  startPos: number;          // Начальная позиция в документе
  endPos: number;            // Конечная позиция в документе
  chunkIndex: number;        // Индекс чанка в документе
}
```

### Результат поиска

Поиск возвращает:

```typescript
{
  rank: number;              // Ранг результата (1, 2, 3...)
  score: number;             // Оценка релевантности (0-1)
  relevance: string;         // Релевантность в процентах
  text: string;              // Текст чанка
  metadata: {
    documentPath: string;
    startPos: number;
    endPos: number;
    chunkIndex: number;
  }
}
```

## Оптимизация

### Размер чанка

- **Малый чанк** (500-800 символов): Более точный поиск, но может терять контекст
- **Средний чанк** (1000-1500 символов): Баланс между точностью и контекстом
- **Большой чанк** (2000+ символов): Больше контекста, но менее точный поиск

### Перекрытие чанков

Перекрытие помогает сохранить контекст между чанками:
- **Без перекрытия**: Может теряться контекст на границах
- **Малое перекрытие** (100-200 символов): Баланс
- **Большое перекрытие** (300+ символов): Больше дублирования, но лучше контекст

### Порог релевантности

В `rag-server.ts` установлен минимальный порог релевантности:

```typescript
const MIN_RELEVANCE_THRESHOLD = 0.5; // 50%
```

Результаты с оценкой ниже порога отфильтровываются.

## Управление индексом

### Пересоздание индекса

```bash
# Удалите старый индекс
rm -rf document_indexer/vectra_index/

# Запустите индексацию заново
cd document_indexer
npm start
```

### Добавление новых документов

Просто добавьте новые файлы в `data/rawData/` и запустите индексацию. Новые документы будут добавлены к существующему индексу.

### Удаление документов

Vectra не поддерживает удаление отдельных документов напрямую. Для удаления:

1. Удалите файл из `data/rawData/`
2. Пересоздайте индекс

## Производительность

### Размер индекса

- Один чанк занимает примерно 1-2 KB в индексе
- Документ в 100 KB создаст примерно 80-100 чанков
- Индекс размером 1 GB может содержать ~500,000-1,000,000 чанков

### Скорость индексации

- Зависит от скорости API OpenRouter
- Примерно 1-2 секунды на чанк
- Документ в 100 KB индексируется за 2-3 минуты

### Скорость поиска

- Поиск по индексу в 10,000 чанков: <100ms
- Поиск по индексу в 100,000 чанков: <500ms
- Поиск по индексу в 1,000,000 чанков: <2s

## Ограничения

1. **Размер документа**: Рекомендуется не более 10 MB на документ
2. **Количество чанков**: Практический лимит ~1,000,000 чанков
3. **API лимиты**: OpenRouter имеет лимиты на количество запросов
4. **Язык**: Система оптимизирована для русского и английского языков

## Решение проблем

### Ошибка "Индекс не найден"

Убедитесь, что индекс создан:

```bash
ls -la document_indexer/vectra_index/
```

Если папка пуста или отсутствует, запустите индексацию.

### Ошибка API при генерации эмбеддингов

1. Проверьте правильность `OPENROUTER_API_KEY`
2. Проверьте баланс на OpenRouter.ai
3. Убедитесь, что модель `qwen/qwen3-embedding-8b` доступна

### Низкая релевантность результатов

1. Попробуйте изменить размер чанка
2. Уменьшите порог релевантности
3. Используйте более конкретные поисковые запросы

### Медленная индексация

1. Проверьте скорость интернет-соединения
2. Увеличьте размер чанка (меньше запросов к API)
3. Используйте локальную модель эмбеддингов (требует дополнительной настройки)
